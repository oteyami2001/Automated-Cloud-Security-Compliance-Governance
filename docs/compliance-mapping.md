# Compliance mapping

**Status: 📝 planned (Phase 1).** This is a **framework-aligned** technical control set. It is
**not** a certification, attestation or claim of compliance with NIST SP 800-53, the CIS AWS
Foundations Benchmark, PCI DSS or SOC 2. Those require scoping, organisational and procedural
controls, and (for PCI DSS and SOC 2) an independent assessor or auditor. None of that is in scope here.

Source of truth: `controls/control-catalog.yaml` (controls) and `controls/<framework>.yaml`
(requirement IDs, titles, versions, sources, verification status). The tables below are
generated by `scripts/render_control_tables.py`, and CI checks they are current.

networking 5.x → 6.x), which the catalog records explicitly.

## 4. Implemented technical controls vs organisational requirements

| Area | What ACSCG implements (technical) | What remains organisational / procedural (not implemented) |
|---|---|---|
| Access control (AC, IA; CIS 1.x/2.x; PCI 7–8; CC6.1–6.3) | Detection of missing MFA, wildcard policies, stale keys; least-privilege roles for the platform itself | Access-control policy, joiner/mover/leaver process, periodic access reviews, identity proofing |
| Audit and accountability (AU; PCI 10) | Detection of trail status, log retention, change events; evidence store with integrity checksums | Daily log review by people (PCI 10.4.1), log review procedures, retention policy approval |
| Configuration management (CM; PCI 2, 6.5; CC8.1) | Policy-as-code in CI, drift detection, unauthorised-change detection | Change advisory process, configuration baselines approved by management |
| Continuous monitoring (CA-7; CC7.1–7.2) | Config rules, EventBridge, dashboards, reports | Continuous monitoring strategy, metrics thresholds owned by management, POA&M |
| Incident response (IR; CC7.3–7.4) | Notifications, escalation of SEC-012/015, GuardDuty sample-finding processing | Incident response plan, roles, training, exercises, external reporting |
| System and communications protection (SC; PCI 1, 3, 4; CC6.6–6.7) | Detection of open admin ports, unencrypted storage, non-TLS bucket access | Network architecture reviews, data-flow diagrams for the CDE, key management procedures |
| Inventory (CM-8; PCI 12.5.1) | Required-tag detection | Asset inventory ownership and scoping |

## 5. Scope statements per framework

- **NIST SP 800-53 Rev. 5:** the mapping names controls (and enhancements) that each technical check
  provides evidence for. It does not select a baseline (Low/Moderate/High) or tailor controls.
- **CIS AWS Foundations:** several recommendations cannot be met in this account as designed (all-Region
  CloudTrail and Config, metric-filter-based monitoring). They are recorded as partial, never as passed.
- **PCI DSS v4.0.1:** no cardholder data is stored, processed or transmitted. Mappings show how the control
  *would* support a requirement in a CDE.
- **SOC 2:** criteria are met by an organisation's whole control environment as reported on by a CPA.
  Technical checks are evidence inputs only.
